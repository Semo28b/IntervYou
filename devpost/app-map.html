LOCAL STREAMLIT APP

AI Mock Interview

Practice a five-question interview grounded in a CV and job title. Python handles the interview rules; Google Gemini creates the interview turns and feedback report.

One answer, from chat to next turn

The main path connects what the candidate does to what appears on screen:

  1. 1. Submit an answer app.py collects it in render_interview_screen().
  2. 2. Apply interview rules interview.py validates answers and tracks questions and follow-ups.
  3. 3. Show the next turn gemini_service.py requests the next utterance; the chat displays it.

After the fifth question, the same app sends the transcript for a report. report.py checks its shape and renders scores, feedback, and CV–job fit. Restart clears the temporary session.

A short code route

This is a reference route prepared from the finished source; it is not a record of editor navigation.

  1. app.py — render_interview_screen() draws the chat and accepts text; process_pending_answer() connects the answer to the interview logic.
  2. interview.py — queue_candidate_answer() checks the answer, while record_interviewer_turn() enforces the five-question and follow-up limits. The matching rules are exercised in tests/test_interview.py.
  3. gemini_service.py makes the model requests; report.py validates and renders the result. Report shape and score checks are in tests/test_report.py.

To change this, start here

  • Screen layout, avatars, chat bubbles, and button colors: app.py, inject_theme_styles() and the screen render functions.
  • Answer validation and question limits: interview.py, with expectations in tests/test_interview.py.
  • Interviewer behavior and model prompts: gemini_service.py. Model IDs belong in the ignored local .streamlit/secrets.toml; never put a real key in source.
  • Report fields and presentation: report.py, with validation tests in tests/test_report.py.
Run and verify the app

From the project folder in PowerShell, with the local environment and settings configured:

python -m streamlit run app.py

Run the offline tests with python -m unittest discover -s tests -v. Use a fake CV for a live demo.

A practice to reuse

Turn a visible requirement into a checkable rule, test that rule without depending on the live model, then try the full journey in the app. Here, report tests verify five distinct question scores, score ranges, and exactly three CV suggestions (tests/test_report.py). The spec describes the expected journey in spec.md → “The Core Journey Through the System”. This makes a mismatch easier to find before a real Gemini response is involved.
